## 2. Every transformation (real pipeline, `run_valuation.py`)

`run_valuation.py:main()` — confirmed by direct read:
1. `data_pipeline.load_historical_salaries` → clean roster
2. `data_pipeline.load_fantasypros_rankings` → full-universe rank/tier table
3. `data_pipeline.expand_pool_with_full_universe` → widen pool beyond the 191 historically-rostered players
4. `data_pipeline.merge_fp_tiers` → attach FantasyPros tier labels
5. `merge_projections` (local function in `run_valuation.py`) → attach `projected_points`, scoring raw stats via `auction_model.config.score_from_stats` when a direct point total isn't present
6. `data_pipeline.fill_anchor_fallback` → fill missing historical-salary anchors
7. `valuation.price_neutral_value` → a *neutral* (pre-keeper-decision) VBD-based value, used as the keeper-decision input, not the final auction price
8. Keeper resolution — **two different paths depending on `--keeper-mode`**:
   - `authoritative` (default): loads `--keepers` (default `outputs/keepers_2026.csv`, plural "outputs", **does not exist anywhere in this repo** — this mode is currently non-functional end to end)
   - `fallback_neutral`: single-pass "neutral alpha" keeper selection via `auction_model.keeper_market` — this is what produced `output_mock_draft_snapshot/keepers_2026.csv`
9. `valuation.price_live_and_hypothetical` → the actual live-auction `suggested_auction_price`, using `config.VBD_DOLLAR_POWER` (convexity exponent, backtested in `backtest_2025.py`) and `config.TIER_SHRINKAGE_PCT`
10. `_reconcile_keeper_budget` → asserts `keeper_spend + remaining_budget == $4,800`, raises if off by >$1

## 4. Source of `suggested_auction_price`

`auction_model/valuation.py:price_live_and_hypothetical` (line 372). Blends
VBD-from-projections with inflation-adjusted historical-salary anchor
(`--blend-weight`, default 0.6), raised to `config.VBD_DOLLAR_POWER` (1.4,
chosen by `backtest_2025.py` against real 2025 season actuals), with
`apply_tier_shrinkage` partially flattening scores toward each
FantasyPros (position, tier) group average (`config.TIER_SHRINKAGE_PCT`,
0.5). Rescaled so the priced pool sums to the live-auction remaining
budget. **No $100 ceiling** (`config.MAX_PRICE = None`, removed in "v4" per
its own changelog comment — an arbitrary cap that was absorbing real value
at the top of the board).

## 5. Source of `projected_points`

Two independent paths, confirmed to have diverged:
- Real pipeline: `merge_projections()` in `run_valuation.py`, scoring
  `data/projections_2026.csv` raw stats via `auction_model.config.score_from_stats`
  when a direct total isn't present. **Bug found and fixed this session**:
  that function only skipped `None`, not pandas NaN — any row missing an
  entire stat category (e.g. a QB row has no receiving columns) silently
  scored the whole player as NaN. Fixed at the source; verified 0 NaN
  afterward. Affected all 158 players this session merged in from raw
  FantasyPros stat exports.
- Mock-draft: `mock_draft/points.py:build_points_lookup()`, re-deriving
  points directly from `data/projections_2026.csv` independently of the
  real pipeline's merge (because the real pipeline's merge only covers
  players matched to the 191-player historical roster, and the mock-draft
  points objective needs every player, keepers included).

These two paths can disagree for any player outside the 191-player
historical-matched pool. Not yet reconciled into one source of truth.

## 6. Keeper source — three separate mechanisms found, none matching reality

1. `auction_model/keepers.py:heuristic_keep_flag` — the original $15-45
   salary-band heuristic. Produced the currently-committed `output/keepers_2026.csv`.
2. `auction_model/keeper_market.py` — a newer "neutral alpha" iterative
   market-clearing keeper optimizer (`iterate_keeper_market`,
   `optimize_team_keeper_portfolio`), invoked via `run_valuation.py
   --keeper-mode fallback_neutral`. Produced `output_mock_draft_snapshot/keepers_2026.csv`.
3. An "authoritative" file path (`outputs/keepers_2026.csv`) that
   `run_valuation.py`'s default mode expects but that has never been
   created — **this mode has never actually run successfully in this repo.**

None of the three encode your stated real keepers. Building a fourth,
genuinely-confirmed path is the first fix required.

## 7. Budget source

`auction_model/config.py`: `NUM_TEAMS=12`, `BUDGET_PER_TEAM=400`,
`TOTAL_LEAGUE_BUDGET=4800`. Per-team live-auction budget = `400 - keeper_spend`
computed from whichever of the three keeper mechanisms above ran.
No mechanism currently subtracts a manual cash trade (e.g. your $15 paid
for Cam Skattebo, or a $1 college-conversion cost) — this does not exist
anywhere in the current code and must be added.

## 8. Auction eligibility source

`auction_model/auction_eligibility.py` — `classify_player_eligibility`,
`filter_veteran_auction_pool`, `build_eligibility_audit`,
`contamination_report`. **Confirmed via grep: `run_valuation.py` never
imports or calls this module.** Its only callers are
`auction_model/roster_optimizer.py`, `run_sam_keeper_analysis.py`, and its
own test file. This means the real pipeline's veteran auction pool
(`output/veteran_auction_price_sheet.csv`) is built WITHOUT this module's
college-rights/keeper-exclusion logic ever running — whatever exclusion
happens in the actual committed output comes from a different, inline
path in `run_valuation.py` and `data_pipeline.py`, not from this
apparently-purpose-built module. This is a real, confirmed duplication:
a correctness-relevant eligibility module exists and is tested in
isolation but is disconnected from the pipeline whose output it's
presumably meant to govern. The confirmed-keeper-mode work should
investigate reusing this module directly rather than building a fifth
parallel eligibility path.

## 9. Fitness calculation (mock-draft optimization layer)

`mock_draft/models.py:Team.total_points` = `sum(points for every one of
the 15 rostered players)`, no lineup legality, no position cap. This is
the exact bug the rebuild spec (§7) asked to audit.

**Confirmed via reproduction this session** (`audit_qb_arbitrage.py`,
reproducing the previously-reported "winning genome" `gen15_elite0` at
its exact original seed/match-count): under this fitness function, the
genome drafts an average of **4.5 quarterbacks per 15-man roster** (range
2-8), spending an average of **$124.91** on QBs alone. Old-objective QB
points averaged **1,302.7** (nearly half the roster's total score);
under a legal-lineup-aware objective built for this audit
(`mock_draft/legal_lineup.py`), that collapses to **228.7** (just the
starting QB plus a small backup-QB bench credit). **15 of 40 reproduced
rosters (37.5%) could not field a legal starting lineup at all** — 10
missing a TE, 3 missing a second WR, 1 missing RB depth, 1 missing FLEX
depth. Full detail: `prior_qb_arbitrage_decomposition.csv` and
`prior_winning_genome_rosters.csv` in this same audit folder.

**Conclusion: the "prioritize QB" result does not survive a legal-lineup
objective. It was an artifact of the flawed fitness function, not a real
strategic insight.** `mock_draft/STRATEGY.md`'s recommendation is invalid
and must be retracted — tracked as a required fix, not yet applied to
that file as of this audit document.

## 10. Bench treatment

None, prior to this audit. `Team.total_points` credits every rostered
player identically regardless of whether they can ever start. This
audit's `legal_lineup.py` adds a first-pass weighted-bench fallback
(§7 of the rebuild spec's suggested weights) but is a minimal

## 11. Final-slot behavior

`mock_draft/auction.py:run_single_auction` — a team's 15th and final
roster slot's price is overridden to equal its entire remaining budget,
regardless of the competitively-resolved bid (`forced_final_slot` flag).
Confirmed present and firing on **40/40** reproduced rosters in the audit
run above (expected, since every roster completes exactly 15 slots under
current code). This is exactly the mechanism the rebuild spec (§10)
requires removing — not yet removed as of this document.

## 12. Price-distribution calculation

`run_player_price_distributions.py` — simulates the recommended genome in
one rotating team seat against 11 hand-designed-archetype opponents,
records every player's price across 100 drafts, computes mean/median/std
+ P10/P25/P75/P90, **excluding** `forced_final_slot` rows from the
aggregation already (organic-only, matching the rebuild spec's intent) —
but the underlying auction mechanics still contain the forced-final-slot
rule for the *other* team slots in the same draft, so those still
influence overall market dynamics indirectly (a flush team dumping cash
late can still win a nomination it wouldn't have organically).

## 13. Evolution training seeds

`run_evolution.py --seed` (default 0) seeds the single `np.random.default_rng`
used for the entire run — population init, every match's team-baseline
computation, every generation's evaluation, and mutation/crossover all
draw from this one stream sequentially. No separate train/validation/test
seed split exists. This is exactly the gap the rebuild spec (§17) flags.

## 14. Evolution validation seeds

None exist as a separate concept. `run_evolution.py`'s "re-evaluate final
population" step and `run_best_response.py` both reuse `--seed + N` offsets
from the same base seed, not an independently-drawn held-out seed set.

- Two `projected_points` derivation paths (§5) that can silently disagree.
